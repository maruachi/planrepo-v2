# PlanRepo 최소 비기능 요구사항

## 상태와 범위

NFR Requirements 산출물 승인 완료: 2026-09-08 사용자 채팅 `진행해줘.`. [계획의 Q1](../../plans/planrepo-nfr-requirements-plan.md)에서 지정한 TypeScript + Fastify + Vue.js를 반영한다. 기술 구성과 준비 조건은 [기술 스택 결정](tech-stack-decisions.md)에 정의한다.

기준은 [요구사항](../../../inception/requirements/requirements.md), [스토리](../../../inception/user-stories/stories.md), [단위 정의](../../../inception/application-design/unit-of-work.md), [업무 규칙](../functional-design/business-rules.md), [알고리즘](../functional-design/business-logic-model.md), [저장 모델](../functional-design/domain-entities.md), [화면 설계](../functional-design/frontend-components.md)다.

전체 MVP 1.5일, 로컬 단일 사용자·단일 앱 프로세스, SQLite 파일 하나, 공개 GitHub 기본 브랜치 읽기와 핵심 경로 스모크만 적용한다. 아래 ID는 기존 승인 내용을 관찰 가능한 조건으로 정리한 것이며 새로운 제품 범위나 서비스 수준 목표를 추가하지 않는다.

## 최소 NFR와 추적성

| ID | 요구 조건 | 근거·스토리 | 담당 | 스모크 확인 |
| --- | --- | --- | --- | --- |
| NFR-01 실행성 | 안내된 런타임·의존성 준비 후 단일 시작 명령으로 로컬 UI와 API를 제공한다. 빌드된 Vue UI는 Fastify가 제공하고 별도 DB·클라우드 계정이 필요 없다 | 실행성, US-01~US-05 | C1, C2, C6 | SM-01 |
| NFR-02 외부 읽기·입력 경계 | 서버에서 저장소 URL·폴더·활성 문서·질문·선택값을 검증한다. 잘못된 호스트는 외부 요청 전에 거부한다. GitHub 외 임의 호스트 우회 요청과 원격 쓰기를 허용하지 않는다. 토큰·계정 정보는 받거나 저장하지 않는다 | FR-1, FR-5, 최소 보안, BR-01, BR-08, US-01·US-04·US-05 | C2, C3 | SM-02, SM-03 |
| NFR-03 표시 안전성 | 외부 문서의 스크립트·위험한 HTML을 실행하지 않는다. 본문만 C5의 SafeHtml로 표시하고 질문·선택지·원문 답변·경고·오류는 텍스트로 표시한다. 렌더링 실패 시 원문 HTML을 직접 출력하지 않는다 | FR-2, BR-12, US-02·US-03 | C1, C2, C5 | SM-02 |
| NFR-04 데이터 지속성 | 최근 성공 연결과 확정 결정·최초 결정 시각·질문 연결 검증 정보를 SQLite에 보존한다. 재시작 후 최근 입력을 복원하고 재연결한 원문에 호환 결정을 적용한다. 문서 전체·미확정 선택·SnapshotId는 영속화하지 않는다 | FR-5, FR-6, BR-05, BR-09, BR-10, US-04 | C2, C6 | SM-03 |
| NFR-05 확정 원자성 | 전체 후보 검증 후 한 트랜잭션으로 저장한다. 한 건의 잘못된 값·충돌·DB 실패에도 전체 롤백한다. 같은 문자 재요청은 행·최초 시각을 유지한 성공이며 다른 값 재확정은 전체 거부한다. 커밋 전에 성공을 표시하지 않는다 | FR-4, FR-5, FR-6, BR-07~BR-09, US-04 | C1, C2, C6 | SM-03 |
| NFR-06 문서·결정 정확성 | 동일 저장소·문서에서 유일한 질문 비교 정보가 일치할 때만 결정을 재사용한다. 비어 있지 않은 원문 답변을 우선한다. 코드·HTML 블록 등의 예시는 질문에서 제외하고 잘못된 영역과 동일 비교 정보 반복 그룹은 경고한다. 내보내기는 확정된 호환 답변만 삽입하고 답변 위치 외 UTF-8 바이트·BOM·줄바꿈·끝 개행을 보존한다 | FR-3~FR-6, BR-03~BR-06, BR-11, US-03~US-05 | C2, C4, C7 | SM-02~SM-04 |
| NFR-07 실패·상태 일관성 | 폴더 없음·접근 불가·네트워크 실패와 정상 빈 폴더를 구분한다. 연결 전체 성공 후에만 활성 컨텍스트·최근 연결을 교체한다. 오류는 code, message, retryable을 제공하고 내부 스택·SQL·비밀정보를 노출하지 않는다. 실패를 빈 결정 목록이나 저장 성공으로 취급하지 않는다 | 오류 처리, BR-02, BR-08~BR-10, US-01·US-03·US-04 | C1~C6 | SM-02, SM-03 |
| NFR-08 조작성 | 라디오 그룹의 질문·선택지 레이블과 키보드 조작을 지원한다. 선택 개수, 읽기·저장 진행, 정상 빈 상태, 경고와 작업별 오류를 텍스트로 표시한다. 저장 실패 시 임시 선택을 유지하고 늦게 도착한 다른 문서·컨텍스트 응답을 현재 화면에 적용하지 않는다 | FR-4, BR-07, BR-09, 화면 설계, US-02~US-04 | C1, C2 | SM-01, SM-03 |
| NFR-09 재현·유지보수 | C1~C7 책임을 같은 구현 단위의 모듈로 유지한다. 런타임과 의존성 고정 기록, 실행·빌드·스모크 안내를 제공한다. 실제 GitHub 결과와 fixture 결과를 구분하고 수행하지 않은 검증을 통과로 기록하지 않는다 | 실행성·테스트 범위, 단위 정의, US-01~US-05 | C1~C7 | SM-01~SM-04 |

범위 표기의 FR-3~FR-6은 FR-3, FR-4, FR-5, FR-6을 포함하며 C1~C7도 각 구성 요소 전체를 뜻한다. 요구사항·스토리·업무 규칙의 상세 의미는 선행 문서가 기준이다.

## 관찰 가능한 스모크 묶음

아래는 후속 구현·검증 계획이며 현재 테스트 결과가 아니다. 별도 광범위 단위·보안·E2E 테스트 모음을 만들지 않고 핵심 여정에 성공과 주요 실패 사례를 묶는다.

| ID | 방법과 입력 | 관찰 결과 |
| --- | --- | --- |
| SM-01 시작·화면 | 고정 환경 준비 후 안내된 단일 명령으로 시작하여 브라우저로 접속. 연결·문서 선택·라디오 키보드 선택·확정·다운로드를 짧게 확인 | Vue 정적 화면과 API가 같은 로컬 앱에서 제공됨. 진행·선택 수·오류·완료 표시와 사용 가능한 동작이 화면 설계와 일치 |
| SM-02 연결·파싱·렌더링 | fixture HTTP 응답을 사용해 문서 여러 개와 빈 폴더·읽기 실패·허용되지 않은 호스트를 확인. 문서에는 미응답·기응답·잘못된 질문, 코드·HTML 예시, 중복 질문 및 위험한 HTML·링크 사례 포함. 실제 공개 GitHub 읽기는 별도로 확인 | 기본 브랜치의 동일 조회 버전으로 문서 집합 생성. 유효 질문과 경고 공존. 거부할 URL은 외부 호출 없음. 읽기 실패 시 기존 컨텍스트 유지. 안전한 본문과 텍스트 표시 확인 |
| SM-03 확정·재연결·재시작 | 실제 임시 SQLite 파일을 사용해 여러 질문 확정, 동일 답변 재요청, 한 후보 오류와 저장 도중 실패를 같은 저장 흐름에서 확인. 앱을 닫고 다시 열어 재연결. 질문 밖 변경·질문 내용 변경·원문 답변 충돌 fixture 사용 | 성공 시에만 대기열 갱신. 전체 롤백·임시 선택 유지, 최초 결정 시각 불변, 최근 연결·결정 복원, 유일한 내용 일치만 재사용, 원문 답변 우선과 경고 |
| SM-04 내보내기 | 여러 확정 답변과 미확정 선택이 있는 문서 다운로드. BOM·CRLF·한글·끝 개행 유무를 포함한 소수 fixture로 기대 바이트 비교 및 다시 파싱 | 해당 답변 삽입 외 바이트 동일, 미확정 선택 미포함, 원문 완료 답변 보존, 재파싱 시 결정 완료. 위치 검증 실패 시 파일 전체 거부. 원격 쓰기 호출 없음 |

실제 GitHub 확인이 네트워크나 요청 한도로 불가능하면 해당 확인을 미수행·제약으로 기록한다. fixture 성공으로 대체 통과를 주장하지 않는다. 런타임 타입 검사와 빌드는 코드 품질 확인이며 테스트 범위를 늘리지 않는다.

## NFR Design 인계

호스트·리다이렉트·폴더 경계 검증, 안전한 렌더러 설정, 로컬 요청 경계, 오류 변환, 동기 트랜잭션과 활성 컨텍스트 변경 순서를 구체화한다. 문자열과 UTF-8 바이트 위치를 혼용하지 않는 파서·내보내기 연결 방식도 포함한다. SQL·파일명·HTTP 경로·DB 위치·실행 명령은 Code Generation 계획에서 확정한다.
