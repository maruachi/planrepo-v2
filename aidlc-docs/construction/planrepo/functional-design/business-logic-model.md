# PlanRepo 기능 흐름과 알고리즘

## 기준과 승인 정책

[기능 설계 계획](../../plans/planrepo-functional-design-plan.md)의 사용자 답변 Q1=A, Q2=A를 2026-09-08 확인했다. 질문 단위로 유일하게 대응하는 저장 결정을 재사용하며, 비어 있지 않은 원문 답변을 우선한다. 두 답변에 모순이나 추가 확인 사항이 없다.

[상위 계약](../../../inception/application-design/component-methods.md)을 구체화한다. 함께 읽을 산출물은 [업무 규칙](business-rules.md), [도메인 모델](domain-entities.md), [화면 설계](frontend-components.md)다.

## 연결·열람 흐름

1. C1 ReviewUI 초기화는 C2 PlanRepoService의 `getRecentConnection`으로 최근 입력을 복원한다. 원문 자동 복원은 없으며 사용자가 연결한다.
2. `connect`는 C3 GitHubSource의 `validateConnection`으로 공개 GitHub 저장소 URL과 저장소 내부 폴더 경로를 검증한다. 루트 폴더는 빈 문자열로 표현한다. 하위 경로까지 `.md` 파일을 탐색하고 저장소 상대 경로 순으로 정렬한다.
3. C3은 기본 브랜치를 한 번 해석한 버전 기준으로 원문 집합을 읽는다. 일부 읽기에 실패하면 연결 전체를 실패로 반환한다. 폴더는 있으나 Markdown이 없으면 정상 빈 집합이다.
4. C2는 각 원문을 C4 QuestionParser에 전달한다. 파싱 경고가 있어도 다른 유효 질문을 유지한다. C6 DecisionStore에서 해당 문서들의 결정을 읽고 아래 병합을 수행한다.
5. 최근 연결 저장까지 성공한 뒤 새 ReviewContext를 활성화하고 WorkspaceView를 반환한다. 이전 컨텍스트를 폐기한다. 실패 시 이전 컨텍스트·최근 연결·UI 임시 선택을 유지한다.
6. `getDocument`는 활성 컨텍스트에 속하는 문서만 C5 MarkdownRenderer로 렌더링한다. 본문은 조회한 원문이며 로컬 결정은 별도 질문 상태로 보여준다. `getWorkspace`는 같은 원문과 현재 저장 결정을 병합하며 외부 원문을 재조회하지 않는다.

## 질문 파싱 알고리즘

기본 지원 문법은 최상위 `## Question <번호>` 제목, 대문자 문자 선택지, 단일 `[Answer]:` 줄이다. 번호는 한 자리 이상의 십진 숫자 문자열이다. `01`과 `1`은 서로 다른 번호로 취급한다. 제목 끝의 공백은 허용하되 번호 뒤 추가 제목 문구는 지원하지 않고 질문 유사 제목에 경고를 남긴다.

1. 원문 UTF-8 바이트를 보존하고 줄별 시작·끝 바이트 위치를 계산한다. 파싱용 줄 끝 제거는 원문 바이트를 변경하지 않는다. UTF-8 BOM은 보존하되 첫 제목 인식을 방해하지 않게 한다.
2. Markdown 블록 문맥을 구분한다. fenced code, 들여쓰기 코드, 인용·목록 내부, HTML 블록·주석 내부의 예시는 실제 질문·선택지·답변으로 인식하지 않는다. 백틱·물결표 fence는 열림과 같은 종류이며 길이가 충분한 닫힘으로 종료한다. 닫히지 않은 fence는 나머지를 코드로 취급하고 경고한다.
3. 질문 영역은 유효한 최상위 2단계 질문 제목에서 시작하여 다음 최상위 1·2단계 제목 또는 문서 끝 직전에 끝난다. 잘못된 질문 제목도 앞 질문의 경계는 종료한다. 3단계 이하 소제목은 현재 영역에 속한다.
4. 질문 문구는 제목 다음부터 첫 선택지 직전까지의 원문이다. 문구가 공백뿐이면 잘못된 영역이다. 선택지는 최상위 줄 시작의 대문자 한 글자와 `)` 및 하나 이상의 공백 뒤 내용으로 시작한다. 다음 선택지 또는 답변 줄 전까지를 해당 선택지의 여러 줄 내용으로 취급한다. 내부 줄바꿈·Markdown은 보존한다.
5. 답변 줄은 최상위 줄 시작의 `[Answer]:`와 나머지 한 줄 값이다. 정확히 하나 있어야 하며 모든 선택지 뒤에 있어야 한다. 값은 공백 제거 후 비어 있으면 미결정, 그 외는 원문 완료다. 원문 완료 값이 선택지 문자 하나가 아니어도 보존하며 경고만 추가한다.
6. 최소 두 개의 선택지가 필요하며 문자는 중복되지 않고 각 내용이 비어 있지 않아야 한다. 연속된 알파벳일 필요는 없다. 답변 뒤 일반 설명은 질문 식별에서 제외한다. 답변 뒤 또 선택지나 답변 표시가 나오면 모호한 영역으로 건너뛴다.
7. 누락·중복 답변, 잘못된 선택지, 빈 문구 영역은 위치를 포함한 경고와 함께 건너뛴다. 코드 예시의 표시는 개수에 포함하지 않는다. Question 유사 제목의 미지원 형식은 경고하며 범용 자연어 질문 추출을 시도하지 않는다.
8. 유효 질문의 비교 정보·현재 답변 값·답변 삽입 위치를 만든다. 문서 안에서 동일 비교 정보가 반복되면 그 그룹을 모호한 질문으로 경고하고 조작 가능한 질문 목록에서 제외한다. 원문 열람·내보내기에서는 해당 영역을 그대로 유지한다.

## 질문 식별과 원문 변경

비교 정보는 `identityVersion=1`, 번호 문자열, 질문 문구, 순서가 있는 선택지 문자·내용 목록의 구조화된 튜플이다. 각 문구의 바깥 빈 줄·앞뒤 공백만 제거하고 CRLF·CR 줄바꿈은 비교용 LF로 통일한다. 내부 공백, 대소문자, 문장부호, Markdown 및 선택지 순서는 그대로 비교한다. 원문 바이트는 별도로 보존한다.

QuestionKey는 DocumentKey와 비교 정보의 버전·다이제스트로 구성하는 불투명 식별자다. 다이제스트만 믿지 않고 저장된 비교 정보도 완전히 일치하는지 검사한다. 서로 다른 비교 정보의 다이제스트 충돌은 자동 연결·저장을 거부하는 경고다. 정규 직렬화·다이제스트 구현은 스택 선택 후 정한다.

동일 저장소·동일 문서 경로 안에서 저장 당시와 현재 모두 유일한 비교 정보이며 저장 문자가 현재 선택지에 있을 때만 호환된다. 문서 앞 소개 문단 추가·질문 이동·답변 값 변경은 비교 정보에 영향을 주지 않는다. 문구·선택지·번호·문서 경로가 달라지면 재사용하지 않는다. 기존 결정을 삭제하거나 새 질문에 추측 연결하지 않는다. 이전 질문 내용으로 되돌아와 유일하게 대응하면 과거 결정을 다시 사용할 수 있다.

## 답변 병합과 상태 전이

| 원문 값 | 호환 로컬 결정 | 유효 상태 | 대기열·다운로드 |
| --- | --- | --- | --- |
| 비어 있음 | 없음 | unresolved | 대기열 표시, 원문 유지 |
| 비어 있음 | 있음 | local_confirmed | 대기열 제외, 저장 문자 삽입 |
| 비어 있지 않음 | 없음 또는 같은 값 | source_answered | 대기열 제외, 원문 그대로 |
| 비어 있지 않음 | 다른 값 | source_answered + conflict | 대기열 제외, 원문 보존과 충돌 경고 |

UI 선택은 unresolved 위의 임시 상태이며 저장 완료 상태가 아니다. 선택 후 확정 성공이면 local_confirmed로 전이한다. 실패하면 unresolved와 임시 선택을 유지한다. 새 원문 조회 시 모든 유효 상태를 다시 계산한다. 원문 값의 비교는 양끝 공백을 제거한 문자열 전체로 하므로 `A 설명`과 저장 문자 `A`는 다르다.

## 일괄 확정·재요청

C2의 `commitAnswers`는 SnapshotId, 비어 있지 않은 선택 목록, 중복 없는 QuestionKey, 활성 문서 소속, 현재 유효 질문과 선택 문자 전체를 검증한다. 원문 답변이 있는 질문이나 다른 답변으로 이미 로컬 완료된 질문의 수정은 거부한다. 같은 문자가 이미 저장된 경우는 재요청으로 성공 처리하며 원래 결정 시각을 보존한다.

검증 후 C2가 서버 UTC 결정 시각과 현재 원문 연결 정보를 설정하고 C6이 한 트랜잭션에서 기존 결정을 재확인하고 신규 결정 모두를 저장한다. 하나라도 실패하면 전체 롤백한다. 신규 저장과 동일 답변 재요청이 섞여도 같은 트랜잭션으로 처리한다. 성공 결과는 실제 저장된 행을 사용해 반환한다. 성공 응답이 유실되면 동일 선택을 재전송하거나 `getWorkspace`로 상태를 복구한다.

단일 활성 컨텍스트를 교체하는 연결과 확정은 C2에서 순서대로 적용한다. 확정이 먼저면 기존 컨텍스트의 저장을 마친 뒤 연결을 교체한다. 연결 교체가 먼저면 예전 SnapshotId 확정은 거부한다. 여러 사용자·분산 동시성·별도 재시도 서비스는 설계하지 않는다.

## 재시작·내보내기

재시작 시 메모리 원문·컨텍스트·임시 선택은 사라지고 SQLite 최근 연결과 확정 결정만 남는다. 다시 연결하여 원문을 읽고 같은 병합 규칙을 적용한다. 기존 SnapshotId는 거부한다.

`exportDocument`는 활성 문서와 C6 결정을 읽고 원문이 비어 있는 유효 질문에 호환되는 확정 결정만 C7 MarkdownExporter에 전달한다. C7은 원문 버전과 답변 위치, 겹치지 않는 변경 범위를 검증한다. 각 답변의 콜론 뒤 기존 수평 공백 다음 위치에 문자 하나를 삽입한다. 공백이 전혀 없으면 문자 앞에 공백 하나도 삽입한다. 나머지 원문·BOM·줄바꿈·파일 끝 개행은 그대로 유지한다. 여러 삽입은 바이트 위치 역순으로 적용한다.

답변이 없는 문서도 원문 그대로 다운로드할 수 있다. 하나라도 위치 검증에 실패하면 파일 전체 생성을 거부한다. HTML 역변환·원격 요청·미확정 선택 반영은 없다. 파일명은 선택 문서의 마지막 경로 요소이며 경로 구분자나 제어문자를 제거한다. 콘텐츠는 UTF-8 Markdown이다.

## 범위와 확장 준수

단일 `planrepo` 로컬 앱, 전체 MVP 1.5일, 핵심 경로 스모크 테스트만 유지한다. 기술 스택은 NFR Requirements에서 결정한다. 실제 HTTP 경로·SQL·실행 명령은 Code Generation 계획으로 넘긴다.

| 확장 | Enabled | 규칙별 결과 | 근거 |
| --- | --- | --- | --- |
| Security Baseline | No | 전체 규칙 N/A | 비활성. 승인된 입력·호스트 검증과 안전한 렌더링은 유지 |
| Property-Based Testing | No | 전체 규칙 N/A | 비활성. 스모크 테스트만 수행 |
| Resiliency Baseline | No | 전체 규칙 N/A | 비활성. 성능·확장성·고가용성·복원력 설계 제외 |

활성 확장 차단 항목은 없다. 이 산출물은 설계이며 구현·동작 테스트 통과를 의미하지 않는다.
