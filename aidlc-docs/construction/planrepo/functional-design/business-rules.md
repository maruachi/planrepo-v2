# PlanRepo 업무 규칙

## 정책 근거

[계획](../../plans/planrepo-functional-design-plan.md)의 Q1=A와 Q2=A를 적용한다. [알고리즘](business-logic-model.md)이 파싱·식별·병합의 기준이고 [도메인 모델](domain-entities.md)이 저장 계약이다.

## 규칙 목록

| ID | 규칙 | 담당 |
| --- | --- | --- |
| BR-01 | 공개 GitHub 기본 브랜치의 지정 폴더·하위 폴더 `.md`만 읽는다. URL·폴더는 서버에서 검증한다 | C2, C3 |
| BR-02 | 전체 문서 집합을 읽고 결정 조회·최근 연결 저장까지 성공해야 활성 연결을 교체한다. 실패를 빈 대기열로 표시하지 않는다 | C2, C6 |
| BR-03 | 기본 질문 문법과 코드·블록 문맥을 적용한다. 잘못된 영역은 경고 후 건너뛰고 다른 유효 질문은 유지한다 | C4 |
| BR-04 | 같은 번호라도 문구·선택지가 다르면 별도 질문이다. 동일 비교 정보가 반복되는 그룹은 오연결을 막기 위해 조작 목록에서 제외한다 | C4, C2 |
| BR-05 | 저장소·문서 경로·질문 비교 정보와 유일성이 일치하고 문자가 유효할 때만 저장 결정을 재사용한다 | C2 |
| BR-06 | 비어 있지 않은 원문 답변이 우선한다. 호환 로컬 답변이 다르면 경고하되 원문과 DB를 변경하지 않는다 | C2, C7 |
| BR-07 | 미확정 선택은 UI에만 존재한다. 확정은 질문별 선택 문자 하나만 저장하며 기타 자유서술·완료 답변 편집은 없다 | C1, C2 |
| BR-08 | 전 후보를 검증하고 C6 트랜잭션에서 저장한다. 중복 질문·잘못된 문자·다른 값 재확정이 하나라도 있으면 전체 실패다 | C2, C6 |
| BR-09 | 같은 저장 문자 재요청은 기존 행·시각을 유지한 성공이다. 실패 시 부분 저장·낙관적 완료 표시가 없다 | C6, C1 |
| BR-10 | 재조회·재시작은 새 컨텍스트를 만든다. 호환되지 않는 기존 결정도 삭제하지 않는다 | C2, C6 |
| BR-11 | 다운로드는 문서 하나, 현재 원문과 호환되는 확정 결정만 적용한다. 답변 위치 외 바이트는 보존한다 | C2, C7 |
| BR-12 | 본문은 C5의 안전한 HTML, 질문·경고는 텍스트로 표시한다. UI는 GitHub·DB에 직접 접근하지 않는다 | C1, C5 |

## 정책 결정 표와 사례

아래 A·B는 실제 해당 질문의 유효 선택지라고 가정한다. 이는 설계 검토 사례이며 실행한 테스트 결과가 아니다.

| 사례 | 대기열과 표시 | 다운로드·저장 결과 |
| --- | --- | --- |
| 빈 답변, 로컬 없음 | unresolved | 원문 그대로 |
| 공백뿐인 답변, A를 화면에서 선택 | 임시 선택 표시, 아직 unresolved | 원문 그대로, SQLite 쓰기 없음 |
| 빈 답변, A 일괄 확정 성공 | local_confirmed, 대기열 제외 | A 반영, 결정 시각 저장 |
| 원문 A, 로컬 없음 | source_answered | 원문 보존, 로컬 결정을 새로 만들지 않음 |
| 원문 B, 호환 로컬 A | source_answered, 충돌 경고 | B 보존, 로컬 A도 보존 |
| 원문 A, 호환 로컬 A | source_answered, 충돌 없음 | 원문 그대로, 로컬 시각 유지 |
| 원문에 선택지에 없는 문장 | source_answered, 형식 경고 | 원문 그대로, 자동 수정 없음 |
| 질문 밖 소개 추가, 빈 답변, 저장 A | local_confirmed | 새 소개 보존, A 반영 |
| 질문 문구·선택지 내용·순서 변경, 빈 답변 | unresolved, 미연결 결정 안내 | 원문 그대로, 기존 결정 보존 |
| 질문 위치만 이동, 유일한 동일 내용 | local_confirmed | 새 답변 위치에 A 반영 |
| 같은 번호지만 문구가 다른 질문 두 개 | 각각 독립 상태 | 각 키에 맞는 답변만 적용 |
| 동일 비교 정보의 질문 두 개 | 모호한 그룹 경고, 조작 목록 제외 | 두 영역 원문 보존, 자동 결정 적용 없음 |
| 문서 경로 변경 또는 다른 저장소 | 새 문서의 unresolved | 이전 문서 결정을 자동 이전하지 않음 |
| 변경 후 과거 질문 내용으로 복귀 | 유일하고 호환되면 local_confirmed | 기존 확정 답변 재사용 |
| 응답 유실 후 같은 A 재확정 | 성공 결과와 최신 상태 반환 | 중복 행 없음, 최초 결정 시각 유지 |
| 확정 목록 중 한 질문의 문자 오류 | 전체 실패, 임시 선택 유지 | 신규 저장 없음 |
| 저장 중 SQLite 실패 | 저장 실패 표시, 임시 선택 유지 | 전체 롤백 |
| 코드 블록 속 질문 예시 | 실제 질문으로 추출하지 않음 | 예시 그대로 |
| 답변 줄 두 개 또는 중복 선택 문자 | 해당 영역 경고 후 제외 | 해당 영역 그대로, 다른 질문은 처리 |
| 재연결 중 문서 하나 읽기 실패 | 연결 실패, 이전 상태 유지 | 최근 연결·결정 유지 |
| 앱 재시작 | 최근 입력 복원, 다시 연결 필요 | 확정 결정 유지, 임시 선택 소멸 |

미연결 결정 안내는 현재 문서에 적용되지 않은 저장 결정이 있다는 정보다. 삭제된 문서의 결정까지 검색해 UI에 노출하는 관리 화면은 추가하지 않는다. 모호한 질문은 완료 건수에도 포함하지 않고 별도 경고로 드러내어 전체 해결로 오인하지 않게 한다.

## 저장 후보 검증 순서

1. SnapshotId가 활성인지 확인한다.
2. 선택 목록이 비어 있지 않고 질문 키가 중복되지 않는지 확인한다.
3. 각 질문이 현재 문서 집합의 유효하고 유일한 질문인지 확인한다.
4. 선택값이 해당 질문의 대문자 선택지 문자 하나인지 확인한다. 클라이언트의 원문·시각·위치는 받지 않는다.
5. 원문 답변이 비어 있는지 확인한다. 이미 저장되었다면 같은 값 재요청만 허용한다.
6. C6 트랜잭션 안에서 기존 값·비교 정보를 재확인한 뒤 전체 저장 또는 전체 롤백한다.

## 오류 결과

| 구분 | 사용자 결과 | 상태 처리 |
| --- | --- | --- |
| 입력 오류 | URL·폴더 수정 안내 | 외부 요청 전 거부 |
| 접근·폴더·네트워크·요청 한도 오류 | 공개 저장소 지원 및 원인에 맞는 재시도 안내 | 기존 활성 상태 유지 |
| 파싱·중복·병합 경고 | 문서 경로·원문 줄 번호·이유 표시 | 영향 영역 외 유효 질문 유지 |
| 만료 컨텍스트 | 다시 연결 안내 | 서버 저장 없음, 미확정 선택은 새 질문에 자동 이식하지 않음 |
| 잘못된 확정 후보 | 해당 선택을 확인하도록 안내 | 전체 저장 거부, UI 선택 유지 |
| DB 조회·저장 실패 | 상태 확인 또는 저장 실패 안내 | 저장 여부를 추측하지 않음 |
| 렌더링 실패 | 안전한 오류 표시 | 위험한 원문 HTML을 직접 출력하지 않음 |
| 내보내기 위치 불일치 | 다시 연결 후 다운로드 안내 | 파일 생성 전체 거부 |

오류는 안정적인 구분값·메시지·재시도 가능 여부를 갖는다. 내부 스택·SQL·비밀정보를 사용자 응답에 포함하지 않는다.

## 범위와 확장 준수

단일 `planrepo` 로컬 앱, 전체 MVP 1.5일, 핵심 경로 스모크 테스트만 유지한다. 기술 스택은 NFR Requirements에서 결정한다. 실제 HTTP 경로·SQL·실행 명령은 Code Generation 계획으로 넘긴다.

| 확장 | Enabled | 규칙별 결과 | 근거 |
| --- | --- | --- | --- |
| Security Baseline | No | 전체 규칙 N/A | 비활성. 승인된 입력·호스트 검증과 안전한 렌더링은 유지 |
| Property-Based Testing | No | 전체 규칙 N/A | 비활성. 스모크 테스트만 수행 |
| Resiliency Baseline | No | 전체 규칙 N/A | 비활성. 성능·확장성·고가용성·복원력 설계 제외 |

활성 확장 차단 항목은 없다. 이 산출물은 설계이며 구현·동작 테스트 통과를 의미하지 않는다.
