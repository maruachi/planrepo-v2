## 설계 기본안

아래는 승인 범위를 구체화할 기본안이다. 정책 답변을 받은 후 상세 산출물에서 확정한다.

- 지정 폴더의 하위 경로까지 `.md` 문서를 탐색한다. 빈 문서 목록과 폴더 접근 오류를 구분한다.
- 기본 질문 형식은 `## Question <번호>`, 대문자 선택지 `A)` 등과 단일 `[Answer]:` 줄이다. 공백만 있는 답변은 미결정, 비어 있지 않은 원문 답변은 완료로 분류한다.
- 코드 블록 안의 예시를 실제 질문으로 추출하지 않는다. 질문 경계, 여러 줄 선택지와 답변 위치는 원문 기준으로 정의한다. 잘못된 영역은 경고와 함께 건너뛰고 유효 질문을 유지한다.
- 질문 번호만으로 저장 결정을 연결하지 않는다. 저장소·문서 경로·질문 내용 검증 정보를 함께 사용한다. 같은 번호라도 내용이 다르면 구분하며 동일 내용의 반복으로 연결이 모호하면 자동 재사용하지 않고 경고한다.
- 서버에서 컨텍스트·질문·선택값 전체를 검증한 뒤 원자적으로 저장한다. 실패 시 일부만 저장하지 않으며 성공한 결정만 완료 표시와 다운로드에 반영한다.
- 승인된 범위대로 선택지 문자 하나만 저장한다. 기타 선택지도 해당 문자를 저장하며 별도 자유서술 필드나 완료 답변 편집 화면은 추가하지 않는다.
- 다운로드는 선택 문서 하나에 대해 수행한다. 미확정 선택을 제외하고 답변 위치 외 원문·줄바꿈을 보존한다.
- 기술 스택·라이브러리·실제 HTTP 경로·실행 SQL·실행 명령은 후속 단계에서 정한다.

## 정책 질문

각 질문의 `[Answer]:` 뒤에 선택지 문자를 입력한다. A는 권장안이며 자동으로 선택되지는 않는다. 다른 정책이 필요하면 X 뒤에 설명한다. 두 답변을 검증한 뒤 계획의 7번부터 진행한다.

## Question 1

문서를 다시 불러왔을 때, 이전에 저장한 답변을 언제 자동으로 재사용할까요? 예를 들어 질문 1은 그대로이고 문서 앞에 소개 문단만 추가된 경우입니다.

A) 질문 단위 확인 (권장) — 같은 저장소·문서 경로에서 질문 번호·질문 문구·선택지 문자와 내용이 같고 유일하게 대응하면 재사용. 질문 밖 문단 변경은 허용하며 질문이나 선택지가 바뀌면 재사용하지 않음

B) 문서 단위 확인 — Markdown 원문 전체가 저장 당시와 같을 때만 재사용. 소개 문단만 달라져도 저장 답변을 자동 적용하지 않음

X) Other (please describe after [Answer]: tag below)

[Answer]:A

두 방식 모두 연결되지 않는 저장 결정을 삭제하지 않는다. 원문 답변이 비어 있고 적용 가능한 결정이 없으면 미결정 대기열에 표시한다. A에서는 답변 줄의 값을 질문 내용 비교에서 제외하고 Q2로 처리한다. B에서는 원문 전체 일치를 요구하므로 원문 답변이 새로 채워져도 로컬 재사용이 차단된다.

## Question 2

같은 질문의 로컬 확정 답변은 `A`인데, 재조회한 원문에는 `[Answer]: B`가 있을 때 어느 답변을 화면의 결정 상태와 다운로드에 적용할까요?

A) 원문 답변 우선 (권장) — 원문이 비어 있지 않으면 그대로 보존. 로컬 결정을 삭제하지 않지만 충돌 경고를 표시하고 원문이 빈 경우에만 Q1 조건을 만족하는 로컬 답변 적용

B) 호환되는 로컬 확정 답변 우선 — Q1 조건을 만족하면 로컬 답변을 적용하고 원문과 다름을 표시. 다운로드에는 로컬 답변을 반영하고 원격 GitHub 원문은 유지

X) Other (please describe after [Answer]: tag below)

[Answer]:A

Q1의 B를 선택하면 원문이 달라진 예시에서 로컬 재사용 조건이 성립하지 않으므로 Q2의 B여도 원문 답변을 유지한다. 본문 뷰어는 상위 설계대로 조회한 원문을 보여주며 적용된 결정은 질문 상태에서 구분한다. 원격 변경, 자동 삭제, 별도 충돌 해결 화면은 추가하지 않는다.
