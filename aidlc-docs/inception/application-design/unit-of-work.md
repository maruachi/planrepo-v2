# PlanRepo 구현 단위

## 검토 상태와 기준

Units Generation 산출물 작성·검증 및 단계 승인 완료. 2026-09-08 검토 질문의 사용자 답변 A를 확인했다. 승인된 [생성 계획](../plans/unit-of-work-plan.md)과 [애플리케이션 설계](application-design.md)에 따라 `planrepo` 단위 하나를 정의한다. 상세 의존성은 [의존성 문서](unit-of-work-dependency.md), 스토리 배정은 [스토리 매핑](unit-of-work-story-map.md)을 참조한다.

## 단위 정의

| 항목 | 정의 |
| --- | --- |
| ID | planrepo |
| 목적 | 공개 GitHub의 Markdown을 읽고 미결정 질문을 정리하여 답변을 보존하고 결과를 내려받는다. |
| 사용자 | P-01 로컬 문서 검토자 |
| 범위 | FR-1~FR-6, US-01~US-05 전체 |
| 실행 형태 | 브라우저 UI와 로컬 앱 프로세스 하나, SQLite 파일 하나 |
| 시간·검증 제약 | 전체 MVP 1.5일, 핵심 경로 스모크 테스트만 수행 |
| 다른 구현 단위 | 없음 |

단위는 개발 작업의 묶음이다. 내부 구성 요소를 독립 서비스나 별도 배포 단위로 분리하지 않는다. 소유자 개인·조직은 지정하지 않으며 앱 전체를 순차 구현한다.

## 구성 요소와 책임

| ID  | 구성 요소            | 책임                                                |
| --- | ---------------- | ------------------------------------------------- |
| C1  | ReviewUI         | 연결 입력, 문서 목록·열람, 질문 대기열, 임시 답변 선택, 일괄 확정과 다운로드    |
| C2  | PlanRepoService  | 입력·조회 컨텍스트 검증, 문서와 저장 결정 결합, 저장·열람·내보내기 조정        |
| C3  | GitHubSource     | 공개 GitHub 기본 브랜치의 지정 폴더 아래 Markdown 읽기 및 읽기 오류 변환 |
| C4  | QuestionParser   | 기본 AI-DLC 질문·선택지·답변 위치 추출과 잘못된 영역 경고              |
| C5  | MarkdownRenderer | 스크립트와 위험한 HTML이 실행되지 않는 표시용 본문 생성                 |
| C6  | DecisionStore    | 최근 연결과 확정 답변을 SQLite에 저장·조회, 일괄 저장 트랜잭션           |
| C7  | MarkdownExporter | 확정 답변을 원문의 해당 위치에 반영하고 나머지 원문을 보존                 |

모든 구성 요소는 `planrepo`에 속한다. 실제 파일·클래스와 모듈 수는 이 표와 일대일 대응할 필요가 없다. 개념적 인터페이스는 [component-methods.md](component-methods.md)를 따른다.

## 입력·출력과 데이터 소유권

| 경계 | 입력 | 출력 |
| --- | --- | --- |
| 초기화·연결 | 공개 저장소 URL, 문서 폴더 | 최근 연결 입력, 문서 목록·질문·경고가 포함된 WorkspaceView |
| 문서 열람 | 활성 SnapshotId와 DocumentKey | 안전한 HTML, 질문 결정 상태와 경고 |
| 일괄 확정 | 활성 SnapshotId와 질문별 선택 문자 | 저장 성공이 확인된 결정과 갱신된 WorkspaceView |
| 문서 내보내기 | 활성 SnapshotId와 DocumentKey | 확정 답변이 반영된 문서 한 개의 Markdown 다운로드 |

| 상태 | 소유 구성 요소 | 보존 범위 |
| --- | --- | --- |
| 선택 문서·미확정 답변 | C1 | 화면 작업 동안만 유지 |
| 원문·원문 버전·파싱 결과·활성 조회 컨텍스트 | C2 | 로컬 프로세스 메모리 |
| 최근 연결 URL·문서 폴더 | C6 | SQLite, 재시작 후 유지 |
| 문서별 질문 식별자·선택 문자·결정 시각·원문 연결 검증 정보 | C6 | SQLite, 재조회 시 연결 가능한 결정만 적용 |
| 안전한 HTML·다운로드 파일 내용 | C5·C7 생성, C2 전달 | 요청 결과 |

C2가 질문·선택값을 전부 검증한 뒤 C6에 일괄 저장을 요청한다. 저장 성공 전에는 완료를 응답하지 않는다. HTML은 파싱·저장·내보내기의 원문으로 사용하지 않으며 미확정 선택은 다운로드에 포함하지 않는다. 문서 전체의 영속 캐시나 오프라인 열람은 요구하지 않는다.

## 단위 내 구현 순서

1. 단일 명령 실행 골격과 SQLite 초기화를 준비한다.
2. 공개 저장소·폴더 연결, 문서 목록과 안전한 본문 열람을 연결한다.
3. 질문 파싱과 모든 문서의 미결정 대기열을 연결한다.
4. 답변 선택·일괄 확정·재시작·재조회 복원을 구현한다.
5. 확정 답변의 문서별 Markdown 내보내기를 연결한다.
6. 실행 안내를 작성하고 핵심 경로 스모크 검증을 수행한다.

이는 후속 Code Generation 계획의 기준이며 현재 구현 완료를 의미하지 않는다. 그 전에 Functional Design, NFR Requirements, NFR Design을 순서대로 완료한다.

## 제외 범위와 후속 결정

인증, 토큰 수집, 비공개 저장소, GHE, 원격 수정·커밋·PR, 다중 사용자, 댓글, LLM, 실시간 동기화, ZIP 일괄 다운로드, 외부 배포는 제외한다. 성능·확장성·고가용성·복원력 설계와 관련 테스트도 제외한다.

Functional Design에서 질문 문법과 코드 블록 경계, 식별자, 원문 변경 판정, 답변 병합 우선순위, 상태 전이, 일괄 저장·내보내기 규칙과 SQLite 모델을 정의한다. NFR 단계에서는 승인된 로컬 실행·최소 보안·오류 조건만 구체화한다.

## 확장 규칙 준수

| 확장 | Enabled | 규칙별 결과와 근거 |
| --- | --- | --- |
| Security Baseline | No | 전체 규칙 N/A. 비활성 결정 유지; FR-2의 안전한 렌더링과 최소 입력·호스트 검증은 유지 |
| Property-Based Testing | No | 전체 규칙 N/A. 자동 검증은 핵심 경로 스모크 테스트로 제한 |
| Resiliency Baseline | No | 전체 규칙 N/A. 성능·확장성·고가용성·복원력 설계 제외 |

전체 확장 규칙 파일은 로드·적용하지 않았다. 활성 확장에 의한 차단 항목은 없다. 이 문서는 구현 보안이나 동작 테스트의 통과를 주장하지 않는다.
