# PlanRepo 단위와 스토리 매핑

## 매핑 기준

모든 스토리는 [P-01 로컬 문서 검토자](../user-stories/personas.md)를 대상으로 하며 `planrepo` 단위 한 곳에 배정한다. [스토리 원본과 인수 조건](../user-stories/stories.md), [요구사항](../requirements/requirements.md), [단위 정의](unit-of-work.md)를 기준으로 한다. 이 매핑은 구현 완료 표시가 아니다.

| 스토리 | 담당 단위 | 요구사항 | 관련 구성 요소 | 핵심 스모크 확인 |

스토리별 인수 조건의 원본은 `stories.md`에 유지한다. 자동화 코드와 결과를 아직 만들지 않았으므로 해당 문서의 미완료 체크박스는 변경하지 않는다.

## 통합 스모크 흐름

공개 저장소·폴더 연결 → 문서 목록·안전한 본문 열람 → 미결정 질문 추출·표시 → 복수 답변 선택·일괄 확정 → 재시작·동일 문서 재조회 → 답변 반영 Markdown 다운로드·재파싱 순서로 하나의 사용자 여정을 확인한다.

원본 스토리의 입력 거부·오류 표시·잘못된 질문 경고·원격 읽기 전용 조건도 같은 핵심 검증 범위에 포함한다. 스토리별로 독립된 광범위 테스트 모음을 요구하지 않는다. 실제 GitHub 확인과 fixture 기반 확인은 구분해 기록한다. 성능·부하·속성 기반·고가용성·복원력 테스트는 제외한다.

## 매핑 검증 결과

- 스토리 5개가 각각 정확히 하나의 단위에 배정되었다.
- FR-1~FR-6이 모두 하나 이상의 스토리에 연결되었다.
- C1~C7의 책임이 배정된 스토리에 포함되며 구성 요소를 별도 구현 단위로 나누지 않았다.
- 모든 스토리는 P-01의 승인된 로컬 사용자 흐름에 속한다.
- 신규 요구사항이나 인수 조건을 추가하지 않았다. 코드와 실행 결과는 후속 단계에 남아 있다.
