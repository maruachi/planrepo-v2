# PlanRepo MVP 사용자 스토리

## 구성 원칙

- 사용자 여정 순서에 따라 성공 경로 중심의 스토리 5개로 구성한다.
- 모든 스토리는 **P-01 로컬 문서 검토자**를 대상으로 한다.
- 인수 조건은 핵심 경로 스모크 테스트로 전환 가능한 체크리스트로 작성한다.

## US-01 공개 저장소와 문서 폴더 연결

**사용자 스토리**: 로컬 문서 검토자로서, 검토할 명세를 불러오기 위해 공개 GitHub 저장소와 문서 폴더를 연결하고 싶다.

### 인수 조건

- [ ] 유효한 공개 `github.com` 저장소 URL과 폴더 경로를 입력하면 연결할 수 있다.
- [ ] 연결 후 기본 브랜치의 지정 폴더에 있는 Markdown 파일 목록을 볼 수 있다.
- [x] GitHub 이외의 URL은 요청 전에 거부된다.
- [ ] 저장소 또는 폴더에 접근할 수 없으면 사용자가 이해할 수 있는 오류가 표시된다.

### 추적성

- **관련 요구사항**: FR-1, FR-2
- **관련 페르소나**: P-01

## US-02 Markdown 문서 탐색 및 열람

**사용자 스토리**: 로컬 문서 검토자로서, 명세 내용을 이해하기 위해 저장소의 Markdown 문서를 선택하고 읽고 싶다.

### 인수 조건

- [ ] 연결된 폴더 아래의 `.md` 파일만 문서 목록에 표시된다.
- [ ] 목록에서 문서를 선택하면 읽기 가능한 형태로 내용이 렌더링된다.
- [ ] 다른 문서를 선택하면 현재 문서 영역이 선택한 내용으로 바뀐다.
- [ ] 문서에 포함된 스크립트나 위험한 HTML은 실행되지 않는다.

### 추적성

- **관련 요구사항**: FR-2
- **관련 페르소나**: P-01

## US-03 미결정 질문 대기열 확인

**사용자 스토리**: 로컬 문서 검토자로서, 아직 필요한 결정을 놓치지 않기 위해 모든 문서의 미응답 질문을 한 대기열에서 보고 싶다.

### 인수 조건

- [x] `## Question <번호>`, 문자 선택지 및 `[Answer]:` 형식의 질문이 추출된다.
- [x] `[Answer]:`가 비어 있는 질문만 미결정 대기열에 표시된다.
- [ ] 각 대기열 항목에 원본 문서, 질문 문구 및 선택지가 표시된다.
- [x] 이미 답변된 질문은 미결정 대기열에 표시되지 않는다.
- [ ] 일부 형식이 잘못되어도 나머지 유효한 질문은 표시되고 파싱 경고를 확인할 수 있다.

### 추적성

- **관련 요구사항**: FR-3, FR-4
- **관련 페르소나**: P-01

## US-04 답변 선택, 일괄 확정 및 유지

**사용자 스토리**: 로컬 문서 검토자로서, 여러 의사결정을 효율적으로 끝내기 위해 질문별 답변을 선택하고 한 번에 확정하고 싶다.

### 인수 조건

- [ ] 각 미결정 질문에서 선택지 하나를 고를 수 있다.
- [x] 여러 질문의 선택 결과를 한 번의 확정 동작으로 저장할 수 있다.
- [x] 확정된 질문은 완료 상태로 바뀌고 미결정 대기열에서 제거된다.
- [x] 애플리케이션을 재시작해도 확정한 답변이 유지된다.
- [x] 같은 저장소와 문서를 다시 불러오면 저장된 답변이 해당 질문에 연결된다.
- [ ] 최근 연결한 저장소 URL과 문서 폴더 경로가 다시 표시된다.

### 추적성

- **관련 요구사항**: FR-4, FR-5, FR-6
- **관련 페르소나**: P-01

## US-05 답변이 반영된 Markdown 내보내기

**사용자 스토리**: 로컬 문서 검토자로서, 결정 결과를 후속 개발 과정에서 사용하기 위해 답변이 반영된 Markdown을 내려받고 싶다.

### 인수 조건

- [x] 확정한 선택지 문자가 해당 질문의 `[Answer]:` 위치에 반영된다.
- [x] 반영된 내용을 Markdown 파일로 내려받을 수 있다.
- [x] 여러 질문에 저장한 답변이 하나의 내보내기 결과에 함께 반영된다.
- [x] 원격 GitHub 저장소의 원본 파일은 변경되지 않는다.
- [x] 내보낸 Markdown을 다시 읽었을 때 해당 질문들이 결정 완료 상태로 해석된다.

### 추적성

- **관련 요구사항**: FR-5, FR-6
- **관련 페르소나**: P-01

## INVEST 검증

- **Independent**: 각 스토리는 저장소 연결, 문서 열람, 질문 확인, 답변 확정, 결과 내보내기라는 구분된 사용자 결과를 가진다.
- **Negotiable**: 사용자 결과와 관찰 가능한 동작을 정의하며 구체적인 구현 구조는 고정하지 않는다.
- **Valuable**: 각 스토리는 문서 탐색 또는 의사결정 처리 시간을 줄이는 직접적인 가치를 제공한다.
- **Estimable**: 입력, 결과 및 완료 조건이 명시되어 범위를 추정할 수 있다.
- **Small**: 스토리마다 하나의 주된 사용자 목표만 다루며 MVP 제외 기능을 포함하지 않는다.
- **Testable**: 모든 스토리에 핵심 경로 스모크 테스트로 확인 가능한 체크리스트가 있다.

## 요구사항 범위 검증

- FR-1부터 FR-6까지 모두 하나 이상의 스토리에 연결됐다.
- 저장소 연결, 문서 보기, 질문 추출, 대기열, 답변 저장, 재시작 후 유지 및 Markdown 내보내기 완료 기준을 모두 포함한다.
- 테이블오더, 인증, 비공개 저장소, GHE, 원격 쓰기, 댓글, 다중 사용자, LLM, 배포 및 복원력 설계는 포함하지 않는다.

완료 표시는 [구현·검증 결과](../../construction/planrepo/code/implementation-summary.md)의 Fastify HTTP·실제 SQLite·실제 GitHub 관찰에 근거한다. 대기열 제거·일괄 확정·다운로드는 API DTO·원자 저장·HTTP attachment로 검증했다. Vue 화면 생성은 완료했지만 브라우저 연결이 없으므로 입력·목록·문서 전환·라디오·최근 입력 표시 등 UI 관찰 조건은 미완료로 남겼다. 브라우저에서 실제 파일 저장은 별도로 확인해야 한다.
