# 로컬 저장소 사용자 스토리 갱신 계획

## 목적과 기준

승인된 로컬 Git 작업 트리 지원 요구사항을 기존 사용자 스토리와 페르소나에 반영한다. 기존의 단일 로컬 문서 검토자, 사용자 여정 기반 분해, 약 5개 핵심 스토리, 체크리스트 인수 조건 결정을 유지한다. 이 변경은 사용자가 문서 소스를 선택하고 로컬 저장소를 연결하는 흐름을 확장하며, 새로운 사용자 역할이나 구현 작업을 추가하지 않는다.

## 실행 체크리스트

- [x] 1. 승인된 요구사항, 기존 페르소나, 사용자 스토리와 사용자 스토리 필요성 평가를 읽고 변경 영향을 확인한다.
  - [x] 공개 GitHub와 로컬 Git 작업 트리의 소스 선택이 직접적인 사용자 기능임을 확인한다.
  - [x] 작업공간 내부 경로, Git 작업 트리, `HEAD` 전용 읽기와 비수정 제약을 확인한다.
- [x] 2. 기존 스토리 생성 결정을 적용한다.
  - [x] 단일 통합 페르소나와 사용자 여정 기반 분해를 유지한다.
  - [x] 체크리스트 인수 조건과 스모크 검증 가능한 범위를 유지한다.
- [x] 3. `personas.md`를 갱신한다.
  - [x] 로컬 Git 작업 트리 검토를 페르소나의 목표, 작업 및 제약에 반영한다.
  - [x] 원격·로컬 소스를 수정하지 않는 제약을 명시한다.
- [x] 4. `stories.md`를 갱신한다.
  - [x] US-01에 소스 유형 선택, 절대 경로 입력, 작업공간 경계, Git 작업 트리 및 `HEAD` 기준 인수 조건을 추가한다.
  - [x] US-02에 로컬 `HEAD` 문서 탐색을 추가하고, US-04에 소스별 저장 결정 분리를 추가한다.
  - [x] US-05에 로컬 작업 트리를 포함한 원본 비수정 인수 조건을 반영한다.
- [x] 5. INVEST, 요구사항 FR-1부터 FR-6, MVP 제외 범위와 인수 조건을 검증한다.
- [x] 6. 갱신된 스토리와 페르소나의 검토 요청을 기록하고 명시적 승인을 기다린다. (2026-09-08 사용자 계속 진행 승인)

## 적용 방식

기존 사용자 여정 기반 구조를 유지한다. 로컬 저장소 지원은 별도 구현 스토리로 분리하지 않고, 소스 연결과 문서 탐색·결정 유지·내보내기 여정의 관찰 가능한 인수 조건으로 추가한다. 이 방식은 기존 다섯 사용자 가치를 보존하면서 원격과 로컬의 동작 기준을 명확히 한다.

## 질문 평가

새 질문은 필요하지 않다. 기존에 승인된 단일 페르소나, 사용자 여정 기반 분해, 성공 경로 중심 세분화와 체크리스트 형식이 이번 변경에도 직접 적용된다. 로컬 저장소의 입력, 경계, Git 작업 트리 및 `HEAD` 정책은 승인된 요구사항에서 구체적으로 결정됐다.
