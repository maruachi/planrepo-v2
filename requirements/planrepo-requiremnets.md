# 문제 정의 및 방향성
PlanRepo는 Spec-Driven Development에서 출발하여 구현을 진행할 때 진행할 때 다수 인원에 대해서 문서, 의사결정 사항, 의견을 공유하고 토의하여 산출물을 효과적으로 통제할 수 있게 하는 서비스이다. 

기존에는 Spec-Driven Development 기반의 개발은 문서 명세를 작성하거나 의사결정 문제를 정리해주는 역할을 보조하지만 팀 단위 공유 및 의견 조율과 같은 협업에 대한 기능을 제공하지 않는다. 이런 Spec-Driven Development에서 협업 문제를 해결할 수 있는 것이 PlanRepo 서비스이다.
# AI DLC 적합성
aidlc는 작은 규모의 개발 할 때는 비효율적일 수 있으며 대규모 개발을 진행할 때 의미가 크다. 대규모에 개발은 다수의 인원에 대한 의견 조율이 필요한 경우가 많고 수많은 문서와 의사결정 사항에 대해서 합의를 진행해야 한다. aidlc는 기본적으로 문서 산출물만 제공하며 적극적으로 공유 및 협의 기능에 대해서는 따로 서비스가 없다. aidlc를 진행할 때 완성된 산출물에 도달할 때까지 문서 공유 및 의사결정 협의는 필수적인 과정인데 이런 부분을 PlanRepo를 통해서 효과적으로 수행한다. 특히나 PlanRepo는 가장 많은 공유와 협의를 해야하는 aidlc 내에 inception 단계에서 가장 효과적이다.

# 기능명세

## 범용 기능 (Spec-driven development 결합형)
- 주요 데이터 구조
	- 문서
	- 의사결정 사항(질문-선택지)
		- 질문: Question1, Question2 태그 기반
		- 선택지: - [ ] A.
- 문서 보기 기능
	- 깃레포 내에 루트폴더 기준으로 Spec 문서 폴더 지정 시에 해당 폴더 내에 마크다운 문서를 볼 수 있다.
- 의사결정 사항 대기 기능
	- 구문분석하여 추출된 의사결정 사항은 미결정된 사항은 대기 상태로 대기열에 나타나서 빠른 접근이 가능하다.
- 의견 요청 사항 대기 기능
	- 의견 요청한 부분에 대해서 대기열에 나타나서 빠른 접근이 가능하다.

- 의사결정 추출
	- 의사결정 사항은 Spec-driven development를 지원하는 툴에서 일관된 양식을 사용한다. 기본 포맷을 선택 가능하며, 질문-선택지 포맷을 지정해서 사용 가능하다.
- github 계정 연동 기능
	- 권한 체크를 기본적으로 github 기반과 연동해서 진행한다.
	- 레포에 대한 권한이 없으면 github를 볼 수 없다. 
	- GHE 기능을 제공한다.
- 의사결정 선택 기능
	- 의사결정 사항에 대해서 선택하여 일괄 반영이 가능하다.
- 문서 토론 기능
	- 문서에 댓글 기반으로 문서에 관련해서 메모를 하거나 간단한 토의가 가능하다.
- 의견 요청 기능
	- 의견 요청은 문서나 문서내 특정 영역 기준 또는 의사결정 사항에 대해서 협의 요청이 가능하다.
	- 협의 요청 지정된 그룹이나 인원은 승인 및 추가 의견을 남길 수 있다.
	- 승인된 의견 요청 기능은 추후에 의사결정 및 
	- 문서를 전면 검토 후 Spec Driven Development에서 다음단계로 진행하기 위해서 프롬프트에 수정 요청사항을 일괄로 요청할 수 있게 문서 수정 요청에 대한 코멘트를 따로 관리한다.
	- 깃 코드 리뷰처럼 실제 문서에 대한 영역을 선택 가능하다.
- LLM 연동 기능
	- 문서 요약 및 시각화 기능
